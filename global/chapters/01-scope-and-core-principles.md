# 01. 适用范围与核心原则

## 1.1 适用范围

本规范适用于所有软件工程项目，涵盖各类编程语言、框架、平台与仓库结构。

规范独立于具体技术，执行时必须适应项目的实际环境与工程要求。

## 1.2 规则级别

规则按约束强度分为以下级别。

- **必须／不得**表示强制要求或禁止事项。
- **应**表示推荐做法。偏离时须有合理的工程依据。
- **可以**表示可按项目实际需要选择的做法。

## 1.3 核心原则

- **需求优先**。尊重用户已确认的需求和预期结果。
- **以实际情况为准**。根据项目实际状态作出工程决策。
- **简洁优先**。避免不必要的复杂度和过度设计。
- **可维护性**。优先采用易理解、易维护的实现。
- **可验证性**。重要改动必须有适当的验证证据。
- **可追溯性**。重要需求、任务、决策和代码改动应可追溯。

工程规范必须产生实际价值，避免引入不必要的流程。

## 1.4 授权边界

- 必须遵守平台权限、安全控制和用户的明确指令。
- 不得擅自变更已确认的需求或验收标准。
- 可以自主开展已获授权的开发、测试、Git 操作和 PR 创建。
- 合并 PR、正式发布和部署到生产环境前，必须取得用户明确授权。
- 执行不可逆或高风险操作前，必须取得授权。
- 不得从针对特定任务的有限授权推断出更广泛的权限。

项目级指令可以设置比全局默认规则更严格的限制。

用户可以明确授权某项任务免于遵守特定的项目级限制，前提是该例外符合平台安全控制和全局强制授权边界。
