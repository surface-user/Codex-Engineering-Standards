# 05. 多 Agent 协作

## 5.1 Agent 组织方式

采用以下分工。

- 主 Agent 统筹工作，是面向用户的唯一沟通窗口。
- Worker 执行主 Agent 分派的任务。
- Reviewer 在需要时独立评审改动。

主 Agent 对整体工程结果负责。

默认最多同时运行三个 Worker。

主 Agent 和 Reviewer 不计入该 Worker 上限。

## 5.2 主 Agent 的职责

主 Agent 必须完成以下事项。

1. 理解用户需求和项目背景。
2. 规划正式开发任务。
3. 确定任务依赖与可并行的工作。
4. 判断是否需要 Worker。
5. 明确分派任务的约定。
6. 跟进进度，处理阻塞。
7. 协调接口与集成。
8. 核验 Worker 的实际交付物。
9. 维护 docs/task.md。
10. 执行最终集成和验收。
11. 向用户报告结果。

主 Agent 不得将最终工程责任转交给 Worker。

## 5.3 Worker 的职责

Worker 必须遵守以下要求。

- 只执行已分派的任务。
- 阅读相关项目指令和背景资料。
- 遵守任务范围、架构与接口约束。
- 编写必要的测试。
- 执行相关验证。
- 报告有实质意义的进展与阻塞。
- 报告完成的工作与未解决的问题。
- 视具体情况提供修改文件、测试证据、提交及 PR 引用。

Worker 不得进行以下操作。

- 擅自变更已确认的需求。
- 擅自重新定义整体项目架构。
- 修改 docs/task.md。
- 未经批准扩大分派的任务范围。
- 删除无关测试或历史记录。
- 隐瞒失败或弱化有效的测试断言。
- 合并 PR 或将正式任务标为 FINISH。

Worker 可以提出改进建议或后续工作，但必须向主 Agent 报告。

## 5.4 任务委派与沟通

主 Agent 必须提供与任务相称的委派约定，包含以下内容。

- **目标**说明必须实现的结果。
- **背景**提供相关项目资料与文档。
- **范围**说明获准修改的边界。
- **约束**说明技术与接口限制。
- **验收**说明分派工作需要满足的完成条件。
- **交付物**说明预期的实现与证据。

Worker 必须报告有实质意义的进展、阻塞、接口冲突和已完成的交付物。

避免不必要的定期状态消息。

Worker 必须根据实际结果汇报完成情况，未经验证不得声称任务完成。

## 5.5 并行执行与隔离

- 有收益时，应并行执行互相独立的任务。
- 排期前必须评估依赖。
- 必须协调重叠的文件改动。
- 并行工作时，应使用独立的 Git Worktree。
- 必须协调共享接口和外部资源的使用。
- 清理前必须检查 Worktree 状态。
- 必须保留未提交的工作和未合并的分支。

协调成本超过预期收益时，不得安排并行执行。

## 5.6 独立评审

Reviewer 是独立调用的评审单元。

重要功能、核心架构变更和高风险工作必须经过独立评审。

Reviewer 必须完成以下事项。

- 检查相关需求与架构约束。
- 找出具体的实现缺陷。
- 评估相关测试与证据。
- 报告安全与集成风险。
- 提出可采取行动的评审意见。
- 提供具体证据，例如文件位置、代码引用或可复现的行为。

评审结果如下。

- APPROVED
- CHANGES_REQUESTED
- ESCALATE

Reviewer 不得直接修改实现代码或原 PR。

原 Worker 应修复自己的 PR。

主 Agent 必须处理上报的问题，并协调必要的用户确认。

普通低风险改动可以由主 Agent 直接评审。

## 5.7 Agent 生命周期

主 Agent 管理 Worker 的创建、复用和结束。

Worker 保有的上下文仍相关且可靠时，可以复用。

Worker 完成任务且没有相关后续工作，或其上下文已不适用时，应结束其运行。

复用或替换 Worker 时，主 Agent 必须提供最新的任务背景。

评审结束后，应结束 Reviewer 的运行。

Agent 生命周期操作取决于当前运行环境及其实际能力。
